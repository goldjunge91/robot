# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project Overview

This is a ROS2 robot package implementing a differential drive robot with sensors (camera, lidar) for both simulation and real hardware deployment. The robot is designed to work in both Gazebo simulation and with physical Arduino-based hardware.

## Common Development Commands

### Build and Setup
```bash
# Build the workspace
colcon build --symlink-install

# Source the workspace
source install/setup.bash

# Clean build (if needed)
rm -rf build install log
colcon build --symlink-install
```

### Simulation
```bash
# Start complete simulation (robot + Gazebo + controllers)
ros2 launch robot launch_sim.launch.py

# Start simulation with custom world
ros2 launch robot launch_sim.launch.py world:=src/robot/worlds/obstacles.world

# Robot state publisher only (for visualization)
ros2 launch robot rsp.launch.py use_sim_time:=true

# Manual control via keyboard
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -r /cmd_vel:=/diff_cont/cmd_vel_unstamped
```

### Real Hardware
```bash
# Launch for real robot
ros2 launch robot launch_robot.launch.py

# Check controller status
ros2 control list_controllers
ros2 control list_hardware_interfaces

# Spawn controllers manually
ros2 run controller_manager spawner diff_cont
ros2 run controller_manager spawner joint_broad
```

### Visualization and Debugging
```bash
# Start RViz with robot visualization
rviz2 -d src/robot/config/view_robot.rviz

# Start RViz with simulation config (includes camera, laser)
rviz2 -d src/robot/config/main.rviz

# Monitor topics and data
ros2 topic list
ros2 topic echo /diff_cont/odom
ros2 topic echo /scan
ros2 topic echo /camera/image_raw

# Joint state publisher GUI (for manual joint control)
ros2 run joint_state_publisher_gui joint_state_publisher_gui

# Image viewer
ros2 run rqt_image_view rqt_image_view
```

### Controller Management
```bash
# Check if simulation is running
ros2 param get /robot_state_publisher use_sim_time

# Monitor controller manager
ros2 run controller_manager list_controllers
```

## High-Level Architecture

### Core Components

**Robot Description System:**
- `robot.urdf.xacro`: Main URDF entry point that conditionally includes components
- `robot_core.xacro`: Defines the basic robot structure (chassis, wheels, dimensions)
- `ros2_control.xacro`: Configures control interfaces (real hardware via Arduino or Gazebo simulation)
- Modular sensor includes: `camera.xacro`, `lidar.xacro`, `face.xacro`

**Launch System Architecture:**
- `launch_sim.launch.py`: Complete simulation setup (Gazebo + robot + controllers + joystick + twist_mux)
- `launch_robot.launch.py`: Real hardware setup with timed controller spawning
- `rsp.launch.py`: Robot State Publisher with configurable sim_time and ros2_control modes
- `joystick.launch.py`: Joystick control setup with twist remapping

**Control Architecture:**
The robot uses a layered control approach:
1. **Hardware Layer**: Arduino-based differential drive OR Gazebo simulation
2. **Controller Layer**: `diff_cont` (differential drive controller) + `joint_broad` (joint state broadcaster)  
3. **Command Multiplexing**: `twist_mux` prioritizes commands (navigation=10, tracker=20, joystick=100)
4. **Input Sources**: Joystick, keyboard teleop, or navigation commands

**Sensor Integration:**
- **Camera**: Standard RGB camera mounted on chassis front, publishes to `/camera/image_raw`
- **Lidar**: 360-degree laser scanner on top, publishes to `/scan` 
- **Odometry**: Generated by differential drive controller at `/diff_cont/odom`

### Key Configuration Details

**Robot Physical Parameters** (from `robot_core.xacro`):
- Chassis: 0.335×0.265×0.138m, wheelbase 0.297m
- Wheels: 0.033m radius, differential drive
- Caster wheel for stability

**ROS2 Control Modes**:
- **Simulation**: Uses `gazebo_ros2_control/GazeboSystem`
- **Hardware**: Uses `drive_arduino/...` via `/dev/ttyUSB0`

**Topic Remapping Strategy**:
- Controllers publish to namespaced topics (`/diff_cont/cmd_vel_unstamped`)
- Twist mux aggregates multiple command sources
- Joystick and teleop remap to controller-specific topics

## Environment Setup

### Required Dependencies
```bash
# Core ROS2 packages
sudo apt install ros-<ROS-DISTRO>-gazebo-ros-pkgs
sudo apt install ros-<ROS-DISTRO>-ros2-control ros-<ROS-DISTRO>-ros2-controllers
sudo apt install ros-<ROS-DISTRO>-gazebo-ros2-control
sudo apt install ros-<ROS-DISTRO>-twist-mux

# Visualization and tools  
sudo apt install ros-<ROS-DISTRO>-rqt ros-<ROS-DISTRO>-rqt-image-view
sudo apt install ros-<ROS-DISTRO>-foxglove-bridge

# Hardware interface (joystick)
sudo apt install joystick jstest-gtk evtest
```

Replace `<ROS-DISTRO>` with your ROS distribution (humble, jazzy, etc.)

### WSL2 USB Setup (if using joystick)
```bash
# In Windows PowerShell as Admin:
usbipd bind --busid 1-1
```

## Key File Locations

- **Configuration**: `config/` - Controller params, RViz configs, joystick mappings
- **Robot Description**: `description/` - All URDF/Xacro files defining robot structure
- **Launch Files**: `launch/` - System startup configurations
- **Simulation Worlds**: `worlds/` - Gazebo environment files
- **Controller Config**: `config/my_controllers.yaml` - Differential drive and joint broadcaster settings

## Troubleshooting Common Issues

**Controller Issues**:
```bash
# If controllers fail to spawn
ros2 control list_controllers  # Check status
ros2 run controller_manager spawner diff_cont  # Respawn if needed
```

**Simulation Issues**:
```bash
# Verify simulation time is enabled
ros2 param get /robot_state_publisher use_sim_time  # Should return True
```

**Hardware Connection**:
```bash
# Check Arduino connection
ls /dev/ttyUSB*  # Should show USB device
```

The project follows standard ROS2 patterns with colcon build system, modular URDF composition, and ros2_control framework integration.
